## H5 修改密码加固（原密码 + 复杂度校验）

问题：`PUT /h5-api/user/resetpwd` 直接 `u.setPassword(user.getPassword())` 覆盖，不校验原密码、无复杂度校验，token 被盗即可改密接管账号。

改动：
1. 新增 `ruoyi-common/.../utils/PasswordPolicy.java`：`check(pwd)` 返回 null 或失败原因，规则 ≥8 位 + 大小写 + 数字。**注册与改密共用此策略**。
2. 新增 `ruoyi-system/.../domain/H5ResetPwdDTO.java`（oldPassword/newPassword）。
3. `IH5UserService` / `H5UserServiceImpl` 新增 `changePassword(userId, old, new)`：原密码校验 → 复杂度 → 新旧不可相同 → 复用 `resetPassword`（内含 BCrypt）。
4. `H5UserCenterController.resetpwd` 改收 DTO，参数缺失返回「参数不完整」，业务校验全部在 Service。
5. `H5LoginServiceImpl.register` 改用 `PasswordPolicy`（提示语保持不变）。
6. `h5/src/views/user/Index.vue`：改密弹窗改为原密码/新密码/确认密码三框，用 `before-close` 提交（失败保持弹窗打开），请求体 `{oldPassword,newPassword}`。

接口破坏性变更：旧客户端只传 `password` 会返回「参数不完整」，属预期。

## 改密配套加固（三项残留风险收口）

1. **改密下线全部会话**：新增 `ruoyi-system/.../token/H5TokenStore.java`（`save/getUserId/remove/removeAllOfUser`）。token 本体仍是 `h5_login_tokens:{uuid}`（纯字符串，勿改 JSON 序列化否则存量 token 读不出），新增用户索引 `h5:user:tokens:{userId}`（Set<uuid>，TTL 7 天）。下线动作放在 `resetPassword` 里，管理员重置与自助改密共用。独立成组件是为了避免 `H5LoginServiceImpl` ↔ `H5UserServiceImpl` 循环依赖（Boot 2.6+ 默认禁止循环引用）。
2. **原密码失败锁定**：`h5:pwd:retry:{userId}`，Redis `INCR` 原子自增，固定窗口（首次计数设 TTL，之后只累加），`getExpire` 兜底无 TTL 键。阈值复用 `user.password.maxRetryCount`(5) / `lockTime`(10min)。
3. **后台重置密码复杂度**：校验下沉到 `H5UserServiceImpl.resetPassword`；`ruoyi-ui/src/views/points/h5user/index.vue` 表单规则由「6~20 位」改为 `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,20}$`。

前端：改密成功后 `userStore.logout()` + `router.replace('/login')`（本次请求的 token 已被服务端下线）。

遗留边界：改造前已签发且未过期的 token 不在索引里，改密后无法批量下线，最长残留 7 天。

## 短信链路清理 / JWT exp / 登录防爆破 / XSS 覆盖 H5

1. **短信验证码整条链路删除**（结论：从来没跑通过）。前端 Tab 已注释、`sendSms()` 打的 `POST /h5-api/auth/sms` 后端不存在、`sendSmsCode()` 零调用，`loginByCode()` 必然失败。已删：前端 `sendSms`/`smsCode`/`sendCode`；后端 `sendSmsCode`/`loginByCode`/`registerOrGet`、`LoginBodyDTO.loginType|code`、`H5_SMS_CODE_PREFIX`/`SMS_EXPIRE_MINUTES`。H5 登录只剩「手机号 + 密码 + 图形验证码」。
2. **JWT 加 exp**：`createToken` 用 `setIssuedAt`/`setExpiration`，有效期与 Redis TTL 共用 `h5.token-expire-minutes`（默认 10080），取值统一走 `H5TokenStore.getExpireMinutes()`。实测：新 token exp 7 天；过期抛 `ExpiredJwtException`；**历史无 exp 的 token 仍可解析**（不会全员掉线）。坑：jjwt 0.9.1 里 `setClaims(map)` 会污染调用方传入的 map（被塞进 iat/exp），createToken 用的是方法内局部 map 所以无影响。
3. **登录防爆破**：单账号 `h5:login:fail:{phone}` 5 次锁 10 分钟；单 IP `h5:login:ip:{ip}` 20 次/分钟（配置 `h5.login-ip-max-per-minute`，比账号阈值宽松以兼容 NAT）。`ensureExpire` 兜底无 TTL 键。
4. **XSS 覆盖 `/h5-api/*`**：`urlPatterns` 加 `/h5-api/*`；**必须排除** `/h5-api/auth/*` 和 `/h5-api/user/resetpwd`——实测 `EscapeUtil.clean("Abc<123>def")` = `Abcdef`，密码含尖括号会被改写导致登录/改密失败。

### 若依 XSS 过滤的实测行为（重要）

- 对整段 JSON 字符串清洗，**双引号不转义**（`validateEntities` 在 `filter()` 里被注释掉了），所以正常 JSON 结构不会被破坏。
- 但字符串里含 `a<b>c` 这类片段时，`balanceHTML` 会在末尾补 `</b>`，导致 JSON 解析失败返回 400。属若依原生限制，不是本次引入。
- `XssFilter.handleExcludeURL` 对 **GET/DELETE 一律跳过**，只过滤 POST/PUT/PATCH。
